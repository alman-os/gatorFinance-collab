# gatorFinance polish judgment pass

Reviewed September 8, 2026, starting with README.md and the current working tree.

**Judgment:** gatorFinance has a credible foundation for a private monthly finance companion. Its next release should make completeness, corrections, and changes over time easy to understand. Keep the distinctive instrument aesthetic; give users more guidance and stronger recovery behavior around it.

The most promising return loop is **import → understand what changed → resolve uncertain entries → save a monthly review → resume next time**. A monthly cadence fits a product that relies on statement exports. Retention benefits below are product hypotheses to test, not measured outcomes.

Scope: README, React interface, CSS, native import/storage/scoring/report paths, and browser interaction with the bundled synthetic demo. No application behavior was changed. The native app was not exercised with real bank records. The production frontend build passes; all nine existing Rust tests pass. Those checks do not establish correctness for every bank, currency, or accessibility scenario.

**Keep these strengths.** Local processing, repeat-import deduplication, preserved overrides, integer money storage, visible score components, EN/ES support, and saved summary artifacts all support the intended relationship. The black/cream surfaces, mono labels, dotted score, and restrained green/yellow accents already have a recognizable identity. A wholesale visual redesign is unnecessary.

## First: make the existing promises dependable

P1 means address before investing in major new features. S = a focused interface change, M = a workflow spanning several components, L = a domain/storage change with broader validation. These are relative scope estimates, not delivery dates. Source paths are relative to the repository root.

| Priority / scope | Before — observed behavior | After — recommended behavior and acceptance check |
| --- | --- | --- |
| P1 / M–L · currency integrity | `src-tauri/src/lib.rs:64` and `:110` calculate dashboard and report values from all transactions. `database.rs:238` chooses the most frequent currency as the display currency. The scoring and category loops do not partition currencies. This can produce a combined total with a misleading currency label. **Code finding.** | Partition analysis and report generation by currency; make the selected currency explicit and prevent a combined score when it lacks a meaningful basis. Keep all imports available. Check with two currencies that neither dashboard nor exported report adds unlike units. Confirm supported currency precision before broadening bank support. |
| P1 / L · coverage honesty | `src-tauri/src/health.rs:139` inserts zero-valued months between the first and last included transaction months. The engine cannot distinguish a missing statement from a genuinely quiet month. A full-looking score can therefore rest on incomplete coverage. **Code finding.** | Show statement coverage per account and month, with distinct missing, partial, and covered states. Use retained import periods where trustworthy and label date-derived coverage as inferred. Treat unverified gaps as unknown in comparisons; define and version scoring changes. Check January + March imports with no February statement: February must be visibly unknown, not silently presented as verified zero spending. |
| P1 / M · protect corrections | `src/components/Transactions.tsx:111` keeps drafts inside an editor keyed to the selected row. Switching rows loses unsaved notes. **Reproduced in demo.** | Preserve drafts per transaction; show Unsaved / Saving / Saved / Failed beside the editor. Offer explicit Save and Discard, and retain failed drafts. Provide undo for saved corrections. Check row switches, navigation away and back, and failed saves. Never label a draft saved until native persistence succeeds. |
| P1 / M · a review queue that finishes | `Transactions.tsx:36` uses only automatic confidence for the Review filter. A user category override does not resolve it, and confirming an unchanged automatic category is stored as `null` at `:119`. Separately, Review can show no matches while the inspector still edits a hidden row. **Filter/inspector mismatch reproduced; resolution defect found in code.** | Store explicit review status independently from automatic confidence, with a “Confirm category” action. Make correction/confirmation clear the queue, add “Save and next,” and keep selection consistent with visible results. Show a completion state when none remain. Check that reopening the app preserves reviewed status, including confirmation of an unchanged category. |
| P1 / M · actionable import and startup errors | The native importer returns per-file errors (`database.rs:127`), but `src/App.tsx:126` only displays aggregate counts. Startup failure leaves the loading shell visible with no Retry (`App.tsx:276`), and the status dot is green whenever not busy, even after failure. **Code findings.** | Show an import receipt with imported / duplicate / failed results per file, a next step, and Retry failed files. Separate initialization failure from loading and add Retry. Distinguish success, warning, and error with text and icons. Check a mixed valid/invalid batch and a failed bootstrap. Guard or queue repeated drops during imports. |
| P1 / S–M · keyboard reliability | Report dialog Escape dismissal fails; repeated Tab reaches navigation behind the open dialog. **Reproduced in demo.** Transaction rows have mouse selection without equivalent keyboard handlers. Below 1120px, CSS hides navigation text without explicit button labels. **Code findings.** | Contain modal focus, make the background inert, support Escape, and restore focus to the opener. Add accessible row-selection controls, named navigation, and announced selected filter/page state. Check keyboard-only import → review → save at the native minimum 960×680 window. |
| P1 / M · report identity and sharing | `src/components/Library.tsx:26` does not clear the old preview or discard stale read responses when selection changes. The visible preview contains artifact JSON, while `src-tauri/src/library.rs:170` later wraps it in an additional AI prompt. README's “exact” preview promise is broader than this implementation. **Code findings; race not reproduced.** | Bind preview loading/error/content to the selected artifact and ignore stale responses. Before sharing, display the exact generated outgoing text and destination, including title and instructions. Disable sharing until that preview is ready. Check rapid A→B selection with delayed A reads: the title, preview, and shared report must all remain B. |
| P1 / S initially · exclusion clarity | The control says “Exclude from score,” but `health.rs:99` and `lib.rs:31` also remove the transaction from dashboard cash-flow and category totals. **Code finding.** | Immediately describe the actual scope: “Exclude from analysis — remains in your ledger.” If score-only exclusion is desired, implement separate flags and distinguish actual cash flow from adjusted score inputs. Check that labels, displayed totals, and report totals tell the same story. |

Modal behavior should follow the [W3C modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): contained Tab navigation, Escape dismissal, and appropriate focus return. This is an interaction contract, not just an ARIA attribute.

## Next: features that make returning worthwhile

| Order / scope | Before — current experience | After — proposed addition |
| --- | --- | --- |
| 1 / M · first-run orientation | Empty state offers an OFX drop/picker and privacy reassurance (`Overview.tsx:76`). A newcomer still needs to know what an OFX export is and what happens next. | Add a brief “Get your statement” guide, supported-format help, and “Explore a sample” in an isolated demo mode with a persistent Sample data badge. Show three steps: Import, Review, Save. Reuse the existing demo idea, but make its counts and actions internally consistent: the present browser mock announces 252 transactions while listing six. |
| 2 / M–L · monthly check-in | Overview shows aggregate history; users cannot select a review month or learn what changed since their last visit. | Add shared month/account/currency scope and a compact “Your monthly review” area: coverage, new transactions, unresolved entries, and one or two explainable changes. Examples are templates, not actual findings: “Dining changed by {amount} across {count} transactions.” Link each observation to the filtered ledger. Allow a short private review note. |
| 3 / M · evidence behind the numbers | Trend chart has no value scale or point interaction; values are exposed only through titles on month labels (`Overview.tsx:26`). Category list stops at eight without a reveal-all action (`:171`). | Add readable scale/zero labels, keyboard and pointer point details, and a compact monthly data table. Clicking a month or category opens its contributing transactions while retaining scope. Add “View all categories” and distinguish period totals from monthly averages. Explain score drivers in plain language, including which penalty values are better when lower. |
| 4 / M–L · corrections that carry forward | Overrides affect one transaction; future imports can require the same manual fixes. | Offer an opt-in “Use this category for this merchant” rule with a preview of affected records and undo. Support bulk category/tag/review actions. Explicit transaction overrides should retain precedence. Scope merchant matches carefully and display why a rule matched. |
| 5 / M · readable saved reviews | Library is dominated by raw JSON (`Library.tsx:80`), with limited help comparing visits. | Default to a human-readable report: period, coverage, income, expenses, net flow, category changes, and caveats. Keep exact JSON behind “View report data.” Compare compatible periods/accounts/currencies and flag engine-version differences. Default titles to the chosen period, and offer “Open saved report” after saving. |
| 6 / M–L · backup and restore | Settings reveals storage paths but provides no backup/restore workflow. Summary reports deliberately omit transactions and cannot restore the working ledger. | Add a clearly separate private backup containing ledger and overrides, with restore preview, validation, and a pre-restore backup. Use a consistent SQLite backup mechanism rather than copying a live WAL database file. Keep private backups outside the AI-share report flow. Check a round trip restores notes, tags, categories, and reviewed states. |
| Later / L · recurring commitments | The native recurring flag is inferred from memo regex matches (`categorizer.rs:162`), not measured cadence. | Build a user-confirmable recurring list from repeated transactions, with typical amount, observed cadence, last seen date, and estimated next occurrence. Label estimates and permit dismiss/correct. This becomes useful once coverage is trustworthy; current regex flags are not enough for a dependable bills forecast. |

For the next product slice, choose the review queue plus the monthly check-in. Together they make progress visible and let the app remember the user's work. Broad CSV mapping can follow evidence that OFX availability is blocking onboarding; it introduces additional parsing and reconciliation scope. Bank sync, investment tracking, autonomous AI recommendations, and gamified daily streaks would expand the promise substantially and are poor priorities for this pass.

## Visual and motion polish

| Before | After — proposed specification |
| --- | --- |
| `src/App.css:469` gives the overview hero a 420px minimum height and a score up to 202px. At the inspected desktop preview, the score dominates while useful analysis falls below the initial viewport. | Keep the Doto score as a signature, but reduce the hero to roughly 240–300px and score to roughly 88–128px where space allows. Put current scope, coverage, and the next review action beside it. Validate the native 1280×820 default and 960×680 minimum before finalizing dimensions. |
| Many essential labels and statuses use 8–10px text; controls often use 34–36px dimensions. Important messages repeat in the global bar and workspace. | Raise essential labels/statuses toward 11–12px and ledger text toward 12–14px, with at least 40px desktop action targets. Keep one global operation status and local feedback near the action. Use sentence case for explanatory copy; reserve compact uppercase for short instrument labels. These sizes are design starting points to validate, not a claim that font size alone establishes accessibility. |
| Navigation, inspector changes, button states, and dialog mounting change abruptly. Existing motion is mostly a loading spinner and stepped status pulse. | Add 120–160ms color/opacity transitions to hover/focus/selection. Use a 160–200ms dialog entrance with opacity and about 4px travel, a softer 100–140ms exit, and immediate input readiness. Cross-fade inspector content over about 120ms without losing focus or draft state. |
| Save/copy confirmation is detached from its control. | Use a local pending → success/error indicator with stable button width and a brief icon cross-fade. Successful feedback must follow confirmed persistence. Optional action-button press feedback can use scale(0.96); avoid scaling table rows or text-entry surfaces. No new animation dependency is needed for these transitions. |
| Score bars and values switch directly when data refreshes. | Briefly transition changed segment colors and highlight the updated summary. Keep exact amounts readable throughout; avoid count-up money animations and a cascading animation across the ledger. Motion should identify what changed without suggesting precision or progress the app cannot measure. |
| The reduced-motion CSS at `App.css:1880` handles keyframe animations but not future transitions. | Extend it to the new transitions: remove spatial travel and continuous effects, with instant updates or short opacity changes. Preserve all status text and focus cues. Validate with the system preference enabled, following [Apple's reduced-motion guidance](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/reduced-motion-evaluation-criteria). |

Preserve the crisp separators instead of replacing every surface with soft cards. Use explicit transition properties, never `transition: all`. Current monetary readouts already benefit from Space Mono; add tabular numerals selectively where proportional type displays changing values. Font smoothing and balanced heading wrapping are finishing touches after legibility and interaction correctness.

## Suggested delivery and evaluation

1. **Reliability pass:** currency/coverage safeguards, draft protection, resolved review state, import receipts, modal keyboard behavior, exclusion wording, and report-preview consistency. Ship small visual legibility improvements with these fixes.
2. **Companion pass:** first-run help, shared period scope, monthly check-in, drilldowns, and readable saved reports. Add restrained feedback motion as these flows stabilize. Prioritize backup/restore before encouraging users to rely on extensive manual enrichment.
3. **Efficiency pass:** reusable merchant rules, bulk review, confirmed recurring commitments, and broader import formats if onboarding evidence supports them.

Validate with five fresh users using synthetic statements: import a valid file plus a malformed one; identify a missing month; resolve an uncertain category; navigate away from an unfinished edit; explain a changed total; save and reopen a review. Include keyboard-only use, English and Spanish, both themes, reduced motion, and the native minimum window. Test large ledgers separately before choosing pagination or virtualization; current full-list rendering is a scalability risk, not a measured performance failure.

Record task completion, time to first useful explanation, lost drafts, unresolved import failures, and whether users can correctly explain the report's scope. For return value, ask participants to repeat the review with another synthetic month and observe whether the app preserves their understanding and prior decisions. Collect this through consented testing rather than adding telemetry to the private product by default.
